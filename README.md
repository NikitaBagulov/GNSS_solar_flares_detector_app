# GNSS Solar Flares Detector App

## Установка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -r requirements.txt
```

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
```

## Быстрый запуск

1. Установить зависимости:

```bash
make install
```

2. Запустить обработку с параметрами по умолчанию:

```bash
make run
```

3. Открыть результаты в браузере:

```bash
make serve-results
```

Затем откройте:

```text
http://localhost:8000
```

## Запуск с параметрами

Чаще всего нужно поменять только даты и минимальный класс вспышки:

```bash
make run START_DATE=2024-11-01 END_DATE=2025-11-12 MIN_FLARE_CLASS=X5.1
```

Если нужно запустить не все шаги:

```bash
make run START_DATE=2024-11-01 END_DATE=2025-11-12 MIN_FLARE_CLASS=X5.1 STEPS="discovery preprocessing index"
```

Если нужно выбрать поведение для уже существующих данных:

```bash
make run START_DATE=2024-11-01 END_DATE=2025-11-12 EXISTING_DATA_POLICY=skip
make run START_DATE=2024-11-01 END_DATE=2025-11-12 EXISTING_DATA_POLICY=overwrite
make run START_DATE=2024-11-01 END_DATE=2025-11-12 EXISTING_DATA_POLICY=validate
```

Service-режим с повтором раз в час:

```bash
make run-service START_DATE=2024-11-01 END_DATE=2025-11-12 MIN_FLARE_CLASS=X5.1 MODE=service POLL_INTERVAL_SECONDS=3600
```

Список всех команд:

```bash
make help
```

По умолчанию pipeline выполняет шаги:

```text
discovery preprocessing index
```

После поиска вспышек pipeline идёт по одной вспышке полностью:

```text
download -> preprocessing -> index
```

## Results directory listing

В карточке события нажмите «Open plot studio»: редактор откроется в отдельной
вкладке. На рабочей области добавьте до 6 панелей (индексы, потоки GOES/SOHO,
карты или солнечный диск с положением вспышки), перетаскивайте их за заголовок и меняйте ширину и высоту мышью за
правый нижний угол. Справа можно точно задать размеры, выбрать ряд данных,
стиль («Simple» — белый научный график с тонкой сеткой, чёрной линией GOES и
зелёной SOHO; «Plotter» — оформление из `Plotter.py`), цвет линии,
 единое время наблюдения из списка существующих меток HDF5 и
 название. Оно действует для всей фигуры: все карты отображают данные в этот
 момент, а на каждом временном ряду проводится одна общая вертикальная линия.
 Если выбрано несколько карт, доступны только метки, имеющиеся во всех их файлах;
 при отсутствии общего времени построение недоступно. Произвольное время указать нельзя.
 Панели не могут перекрываться — это проверяют и редактор,
и сервер при генерации. Предпросмотр показывает границы каждой панели,
 заголовок, расположение осей и подписей, метки события и выбранного времени наблюдения, стиль линий и фона, а для
карт — цветовую шкалу; итоговый PNG с данными появляется после нажатия
«Generate plot». Оформление карт в обоих стилях повторяет `Plotter.py`: палитры,
диапазоны, географическая подложка и терминатор. Подписи времени — UTC.
Научный заголовок описывает измерения (например, ионосферный отклик на вспышку),
 а подзаголовок содержит дату события и выбранное время наблюдения; время начала, максимума,
окончания и координаты HPC добавляются из `data/all_flares.csv` (при отсутствии
данных — `data/flare_position_catalog_hek.csv`), если вспышка однозначно
 идентифицирована. Поле редактора добавляет свою подпись под заголовком.
 Для научного графика временные ряды автоматически показывают общий интервал
 вокруг вспышки (не менее часа), если данные и времена начала/конца доступны;
  пунктиром отмечены начало и конец, красной линией — максимум, а коричневым
   пунктиром — единый момент наблюдения. Общая легенда поясняет метки в обоих
  стилях. За пределами
 интервала данные не учитываются при подборе масштаба оси Y. На отдельных
 панелях используются физические единицы измерения, краткие названия рядов и
  время наблюдения с точностью до минуты без микросекунд.
Солнечный диск повторяет отображение `Plotter.py`: используется доступное изображение
из `solar_image/`, иначе схематический диск; маркер ставится только при наличии
подтверждённых координат HPC.
Введите адрес почты как идентификатор результата: письма не отправляются.
Результат появляется в редакторе, а ссылка открывает PNG в полном размере.
На главной странице каталога в разделе
«My plots» введите тот же адрес, чтобы увидеть все свои графики за последние
три дня и открыть или удалить их. Адрес не подтверждается: любой, кто знает
его, может найти связанные с ним графики. Временные PNG и сведения о запросах
хранятся в `results/.plot-cache/` и очищаются при обращениях к графикам.
Предварительная генерация графиков при `make run` отключена; для прежнего режима
укажите `STEPS="discovery preprocessing index plotting"`.

Если порт `8000` занят:

```bash
make serve-results RESULTS_PORT=8001
```

## Проверка готовности уже вычисленных событий

Показать, какие карты, индексы и графики уже существуют и какие события можно
быстро довычислить:

```bash
python3 -m analysis.event_readiness --results-dir results
```

Сохранить полный отчёт в CSV:

```bash
python3 -m analysis.event_readiness \
  --results-dir results \
  --output analysis/event_readiness.csv
```

Вывести только события с готовыми картами и отсутствующими индексами:

```bash
python3 -m analysis.event_readiness \
  --results-dir results \
  --status ready_for_index \
  --format events
```

Пересчитать индексы для выбранных событий напрямую из уже готовых HDF5-карт:

```bash
python3 -m analysis.recompute_existing_indices \
  --results-dir results \
  --events 2025-11-11_X5.2 \
  --policy overwrite \
  --backup-existing \
  --report analysis/recompute_report.csv
```

Последовательность вычислений для статьи приведена в
[`docs/SERVER_COMPUTATION_STAGES.md`](docs/SERVER_COMPUTATION_STAGES.md).

State и скачанные данные по умолчанию:

```text
data/state.json
data/
```

При загрузке `simurg_hdf` в консоли должен появляться размер файла и прогресс загрузки. Ограничения по времени загрузки не задаются.
